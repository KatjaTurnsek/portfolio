Luma Stays

A complete accommodation booking app built for customers and venue managers.

Role
UX/UI design and front-end development
Scope
Individual Project Exam 2
Year
2026
Tools
React, JavaScript, Bootstrap, Noroff API
Outcome
Grade A

The brief

The task was to turn the Holidaze API into a complete accommodation booking app. Customers needed to find venues, check availability, make bookings, and manage upcoming stays. Venue managers needed a different set of tools for creating listings, editing venue details, and reviewing bookings. Both journeys had to live within the same application without making the interface feel crowded or confusing.

Challenge

The application supports public visitors, registered customers, and venue managers. What someone can see or do depends on their account type, authentication state, and relationship to a venue. Booking availability also changes with dates and guest numbers. The main challenge was keeping those rules accurate while giving each user a clear path through the app.

  • Support customer and manager journeys without building two separate interfaces
  • Keep venue, profile, and booking data accurate after API mutations
  • Handle loading, validation, empty states, and API errors without breaking the flow

Key decisions

  • I organised the app into routed React views and reusable components for venue cards, forms, navigation, feedback messages, and protected actions. Shared patterns stay consistent, while each page keeps control of its own task.
  • The interface checks authentication, account type, and venue ownership before showing protected controls. Customers see booking actions, while managers get the tools needed to create and maintain their venues.
  • Search matches several parts of the venue data rather than relying on the title alone. Guest filtering is handled separately, which makes the results more useful even when the API content is inconsistent.
  • Forms preserve the user’s input when a request fails and provide clear feedback for validation, authentication, bookings, profile changes, and venue updates. Successful actions also refresh the relevant data so the interface reflects the latest API state.

Outcome and reflection

Luma Stays received a Grade A and delivers complete customer and venue-manager journeys in one responsive React application. Building it gave me solid experience with authentication, role-based access, routed views, API mutations, and state that changes across several parts of an interface. It also confirmed something I care about in my work: complex functionality does not need to look complex. Good structure and clear feedback can keep a demanding booking flow calm and easy to follow.

Little Joy Shop

A responsive React shop that takes users from product discovery to a completed checkout.

Role
UI design and front-end development
Scope
Individual JavaScript Frameworks assignment
Year
2025
Tools
React, TypeScript, Bootstrap, REST API
Outcome
Complete e-commerce flow

The brief

The assignment was to build a complete online shop using a supplied product API. Users needed to browse and search the catalogue, open individual product pages, manage a cart, complete checkout, and receive a clear confirmation. Each part had to work as its own view while still feeling like one connected journey.

Challenge

Several parts of the interface rely on the same changing data. Adding an item affects the cart count, quantities, calculated totals, and checkout summary. That information also has to remain correct while the user moves between routed views. The main technical challenge was keeping those states consistent without making the component structure difficult to follow.

  • Define predictable product and cart data with TypeScript interfaces
  • Keep quantities, prices, discounts, and totals accurate across the shop
  • Handle loading, API errors, empty carts, and unsuccessful searches clearly

Key decisions

  • I created typed models for the API responses and cart items. This made the data contract visible in the code and reduced guesswork when products were passed between components.
  • Repeated interface patterns became reusable React components, including product cards, navigation, form elements, and feedback messages. Page-specific logic stayed within the routed views where it was easier to understand.
  • Cart totals are calculated from the current cart state instead of being stored as separate values. This avoids stale totals when a user changes a quantity or removes an item.
  • I treated empty and unsuccessful states as part of the interface. A no-results message explains what happened, while the cart summary keeps prices and the next step easy to find.

Outcome and reflection

The finished project covers the full shopping flow in a responsive React and TypeScript application. It gave me practical experience with typed API responses, shared state, routed views, reusable components, and values derived from changing cart data. It also sharpened my view of feedback in interface design. A blank search result or an unclear total may look like a small problem, but both can make a working shop feel unreliable.

The artwork had to lead the experience, but not at the expense of useful information or straightforward navigation.

Detailed paintings need large, high-quality images to be appreciated properly. Those same images can make a page slow, especially on mobile. The site uses animated backgrounds, page transitions, theme switching, and fullscreen navigation. The portfolio now works as both a presentation of my projects and a front-end project in its own right. Its visual character comes from my design background, while the code demonstrates modular JavaScript, client-side routing, reusable data, responsive assets, theme logic, and accessible motion. I keep refining it as the content grows. That process has made me more selective with animation. An effect earns its place when it supports the atmosphere or helps the interface feel responsive. StudioBid

An API-driven auction platform for browsing, selling, and bidding on creative work.

Role
UX/UI design and front-end development
Scope
Individual Semester Project 2
Year
2025
Tools
JavaScript, Bootstrap, Sass, Noroff API
Outcome
Complete auction platform

The brief

The task was to turn the Noroff Auction API into a working front-end application. Anyone should be able to explore active listings. Registered users also needed to create auctions, place bids, update their profiles, and follow their available credits. These actions depend on authentication and live API data, so the interface had to make the user’s current status and available actions clear.

Challenge

Auction data changes quickly. A successful bid can update the current price, the bid history, and the user’s remaining credits in a single action. Listings can also expire, and owners need different controls from bidders. Keeping those relationships accurate across listing cards, detail pages, forms, and profiles was the central technical challenge.

  • Allow public browsing while protecting actions that require an account
  • Keep bids, credits, ownership, and listing status in sync with the API
  • Make validation, loading states, and API errors clear without disrupting the task

Key decisions

  • I separated API requests, authentication, rendering, and form handling into focused JavaScript modules. Shared behaviour stays in one place, while each page controls the logic that belongs to its own task.
  • Authentication is stored between page visits and checked before protected actions. Visitors can still browse freely, but bidding, profile editing, and listing management only appear when the user has permission to use them.
  • Listing cards focus on the information needed for an early decision: the current bid, time remaining, image, and listing title. The detail page adds the seller, full description, bid history, and relevant actions.
  • Forms use shared validation and feedback helpers so fields behave consistently. Successful requests update the visible interface, while API errors explain what went wrong without clearing the user’s input.

Outcome and reflection

StudioBid brings public listings, authentication, bidding, credits, profiles, and auction management into one responsive application. Building it in vanilla JavaScript forced me to be deliberate about module boundaries and the flow of data between API requests and rendered views. The project also exposed a basic truth about transactional interfaces: the user needs to see the result of an action immediately. If a bid changes their credits but the page does not show it clearly, the code may be correct while the experience still feels uncertain.

Luma Stays

A calm accommodation platform designed around confident booking and practical venue management.

Role
UX/UI design and prototyping
Scope
Individual Project Exam 2
Year
2026
Tools
Figma, responsive UI, prototyping, design system
Outcome
Grade A project

The brief

Luma Stays needed to support two connected but very different journeys. Customers had to search a large catalogue, compare venues, check availability, and complete a booking. Venue managers needed to create listings, maintain venue information, and review bookings. I designed both sides as parts of the same product, using shared patterns where they made sense without forcing different tasks into identical layouts.

Challenge

Choosing accommodation involves several decisions at once. Price, location, capacity, facilities, images, and availability all matter, but presenting everything with equal weight would make the interface difficult to scan. The design needed to reveal enough information for each decision while keeping search and booking straightforward.

  • Make venue cards useful for comparison without overloading them
  • Keep search and filters connected to the results they change
  • Give booking controls enough emphasis without pushing venue information aside

Key decisions

  • I limited venue cards to the details needed for an initial comparison: image, title, location, guest capacity, rating, and price. The full venue page carries the information needed for a final decision.
  • Search and guest filtering sit close to the results so users can see what changed. The controls remain easy to adjust instead of disappearing once the catalogue updates.
  • On the venue page, I separated descriptive content, facilities, practical details, and booking controls into distinct areas. This allows users to evaluate the stay without losing sight of the next action.
  • I used a restrained colour palette, generous spacing, and repeated card and form patterns to give a content-heavy product a quieter rhythm. Responsive layouts were designed around task priority rather than simply stacking every desktop element.

Role-based flow

Customers and venue managers use the same authentication, navigation, and profile foundation, but their priorities are not the same. Customer profiles focus on planned stays and booking history. Managers need immediate access to the venues they own and the actions required to maintain them. I kept the shared structure familiar while changing the content hierarchy and available controls according to the user’s role.

  • Customer profiles place upcoming and previous bookings first
  • Manager profiles surface owned venues and listing-management actions
  • Editing controls appear when ownership makes them relevant, keeping the public experience uncluttered

Outcome and reflection

The final design connects discovery, venue comparison, booking, profiles, and listing management without treating them as isolated features. The completed application received a Grade A. The most valuable part of the project was designing one system for users with different permissions and goals. It pushed me to think beyond individual screens and consider what information should persist, what should change with the user’s role, and when an action needs to become visible.

StudioBid

An auction platform designed to make changing prices, deadlines, and bidding decisions easier to understand.

Role
UX/UI design and prototyping
Scope
Individual Semester Project 2
Year
2025
Tools
Figma, wireframing, responsive UI, component system
Outcome
Complete auction journey

The brief

StudioBid needed to turn an auction API into a clear experience for discovering, selling, and bidding on creative work. Visitors should be able to browse without an account, while registered users needed access to bidding, listing creation, credits, and profile activity. The design had to connect these journeys and make changing information, such as the current bid and time remaining, easy to interpret.

Challenge

Auction interfaces ask users to make decisions with incomplete and changing information. A listing may receive a new bid, approach its deadline, or become unavailable while someone is viewing it. Users also need to understand how a bid affects their credits before they commit. The interface had to communicate these states without making every screen feel urgent or crowded.

  • Make the current bid, time remaining, and listing status easy to scan
  • Show the relationship between a bid amount and the user’s available credits
  • Keep actions and feedback predictable as listing states change

Key decisions

  • I structured listing cards around the information needed for an initial comparison: image, title, current bid, and time remaining. Seller details, descriptions, and bid history belong on the listing page, where users are making a more considered decision.
  • The current bid and primary action receive the strongest emphasis on the detail page. Credits and bidding history remain visible nearby so users can judge the consequences of placing another bid.
  • I defined reusable cards, buttons, badges, fields, and feedback states before applying them across the product. This kept browsing, bidding, selling, and profile views visually connected without forcing every task into the same layout.
  • Protected and unavailable actions were designed as meaningful states. Instead of leaving a disabled control unexplained, the interface tells users when they need to sign in, increase their bid, or choose a listing that is still active.

From flow to system

I began by mapping the main journey from browsing to opening a listing and placing a bid. Profile activity introduced another layer: users needed to distinguish between auctions they created, items they had bid on, and auctions they had won. The wireframes helped turn those relationships into one repeatable dashboard structure.

  • Kept the browse, listing-detail, and bidding flow short and direct
  • Separated selling activity, active bids, and wins within the profile
  • Reordered content and controls on smaller screens according to task priority

Outcome and reflection

The final design supports browsing, bidding, selling, and account management through one consistent interface. Working through the auction states before development helped expose conditions that a static happy-path design would miss: expired listings, insufficient credits, ownership, authentication, and bids that are no longer high enough. The project taught me to consider the whole interaction: what users see before they do something, what happens while it is being processed, and whether the result is clear afterwards.

Heart Asylum

A dark logo suite and atmospheric release artwork created for an alternative rock duo.

Role
Logo design and cover artwork
Scope
Real-world music branding
Deliverables
Logo suite and single cover
Tools
Adobe Illustrator, Photoshop
Outcome
Release-ready visual identity

The brief

Heart Asylum needed a recognisable identity that matched the dark, alternative character of the duo's music. It had to work across several formats, including streaming platforms, social graphics, posters, and release artwork. The single cover also needed to feel connected to the identity while having its own composition and atmosphere.

Challenge

Music branding needs to communicate a mood quickly, but many people first see it as a small image on a streaming or social platform. The main challenge was creating something expressive and detailed that would still have a clear silhouette and remain recognisable when reduced in size.

  • Balance a dramatic visual style with clarity at smaller sizes
  • Create a system that could work as an icon, wordmark, or complete logo
  • Connect the logo and cover artwork without using the same composition twice

Key decisions

  • I built the emblem around a heart with sharp, architectural linework. This connects the emotional meaning of the name with the harder edge of the music.
  • I created primary, secondary, icon, wordmark, and reversed versions so the identity could adapt to different backgrounds and formats.
  • For the cover, I used high-contrast wing linework as the main visual element, with restrained typography and portrait detail supporting the atmosphere.
  • I checked the square artwork at a smaller size to make sure the wings, title, and band mark kept a clear visual hierarchy.

Outcome and reflection

The result is a connected set of assets rather than only one logo. The different logo versions provide practical options for small digital placements and larger graphics, while the cover carries the same dark character in a more atmospheric way. This project helped me develop a visual system that communicates the feeling of the music while still working across very different sizes and formats.

Merlin’s Big Surprise

A complete children’s book illustration commission developed from traditional pencil sketches to finished digital artwork and publication.

Role
Illustrator
Client
Author Agi Kiss
Scope
Commissioned children’s book
Tools
Pencil, scanner, Photoshop, drawing tablet
Outcome
Published and translated internationally

The story behind the project

Merlin’s Big Surprise is a children’s story written by Agi Kiss about Merlin, a cautious rabbit who prefers a quiet and predictable life, and Ping-Pong, an adventurous kitten who unexpectedly becomes his friend.

The characters were inspired by the author’s real pets, making it important that their personalities and relationship remained recognisable throughout the illustrations.

Challenge

The author approached me after earlier illustration attempts had not achieved a visual direction that met the publisher’s detailed requirements. My task was to develop and complete a consistent illustration set and carry the visual work through approval to publication.

  • Communicate two contrasting personalities clearly for young readers
  • Keep the characters’ markings, proportions, and expressions consistent
  • Compose each scene around text areas, page edges, and centre folds
  • Develop the complete project through feedback and revisions

Planning and revising the visual story

I began by translating the manuscript into hand-drawn compositions. The sketches established the character positions, environments, visual focus, and reading flow before I started the finished artwork.

Planning the scenes on paper made it possible to solve the storytelling early while leaving suitable space for the accompanying text. I also needed to consider page edges and the centre fold so that important character details would remain clearly visible in the printed book.

This revision stage was an important part of the commission. Each change needed to work within the individual scene while also maintaining the same character markings, proportions, colour treatment, and visual style used throughout the book.

  • Establish the composition and character positions through sketches
  • Leave appropriate space for text, page edges, and the centre fold
  • Incorporate author and publisher feedback into the finished artwork
  • Maintain visual consistency across the complete publication

From sketch to finished artwork

After establishing each composition, I scanned the sketches and developed the final illustrations in Adobe Photoshop using a drawing tablet. I refined the characters, expressions, textures, lighting, colours, and environmental details while preserving the structure of the original drawings.

Traditional sketch

This drawing established Merlin’s pose, the window, and the surrounding room before digital painting began. It also helped define where the illustration needed detail and where quieter space should remain.

  • Establish the character’s pose and expression
  • Plan the surrounding environment
  • Resolve the composition before digital production

Digital production

The final illustration retained the original composition while developing the scene through colour, texture, lighting, and depth. Working digitally allowed me to refine the character’s fur, markings, and expression while keeping the softness of the original drawing.

The open area around Merlin was kept intentionally restrained so that the finished illustration could work together with the book’s text and page layout.

Printed storytelling

The completed spreads show how the illustrations work together with the story text. Some scenes focus on quieter character moments, while others use action and more detailed environments to change the pace and guide the reader through the story.

Character and personality

Merlin’s cautious nature and Ping-Pong’s curiosity needed to remain visible through their expressions, poses, and interactions. The cherry-tree scene uses the characters’ positions and eye lines to make their contrasting personalities immediately clear.

  • Merlin remains grounded and hesitant
  • Ping-Pong occupies the more adventurous position
  • The spread balances illustration with readable text areas

Consistency across the book

Maintaining recognisable characters across different environments and emotional situations was an important part of the project. Their markings and proportions needed to remain consistent whether they appeared in a quiet interior or an action scene.

The fishpond spread also required a more complex environment with water, plants, a frog, movement, and interaction between both main characters.

Outcome and reflection

I completed the full illustration set and carried the visual work through revisions and approval to publication. Merlin’s Big Surprise was produced as a physical book, translated into several languages, and made available through international retailers.

The project demonstrates my ability to manage a detailed, long-form illustration commission from early sketches and character development through digital production and final publication. It also strengthened my experience in visual storytelling, character consistency, print preparation, and responding carefully to detailed client and publisher feedback.

Pet Art With Heart

A hand-drawn identity that brings together pet portraiture, fine art, and the emotional connection people have with their animals.

Role
Brand design and illustration
Scope
Independent real-world brand
Status
Ongoing
Tools
Pencil and paper, Adobe Illustrator
Outcome
Flexible brand identity

The brief

Pet Art With Heart is my own pet portrait business, so the identity needed to feel personal while still looking established and professional. I wanted one recognisable symbol that could connect pets, art, and the meaning behind the word “heart.” It also needed to work across the website, social media, profile images, and printed material without losing its character.

Challenge

The idea included several visual elements: a dog, a cat, a heart, and an artist's palette. Combining all of them too literally would have made the logo complicated and difficult to recognise at a smaller size. The main challenge was finding a simple form that communicated the idea without feeling like a collection of separate symbols.

  • Connect pet companionship and artistic work within one symbol
  • Create something emotional without making it overly playful
  • Keep the character of the original drawing during vector refinement

Key decisions

  • I used the curved silhouettes of the dog and cat to form a heart through their shared negative space instead of adding a separate heart shape.
  • The palette holes are integrated into the cat's body. This keeps the reference to painting visible without adding another standalone object.
  • I paired the organic symbol with a classic serif wordmark to balance the warmth of the illustration with a more established and trustworthy feeling.
  • I created horizontal, vertical, icon-only, monochrome, and reversed versions so the identity could adapt to different formats and backgrounds.

Outcome and reflection

The finished identity connects my fine-art work with a practical brand system. The icon is detailed enough to feel personal but simple enough to remain recognisable as a small profile image. The different lockups also give me flexibility when adding the logo to new formats. This project showed me how an expressive pencil sketch can keep its original personality after being simplified and prepared for real-world use.

Agility Bandits

A playful identity built around a real agility dog, with supporting graphics inspired by speed, movement, and the chaos of the sport.

Role
Brand design and vector illustration
Scope
Individual Project Exam 1
Year
2024
Tools
Adobe Illustrator
Outcome
Social-to-web brand system

The brief

Agility Bandits began as an identity for sharing dog-agility content and later developed into a complete blog brand. I wanted the design to keep the personality of Roi, my red-and-white Border Collie, while also expressing the speed, humour, and unpredictability of the sport. The identity needed to work across profile images, navigation, page graphics, and larger website layouts.

Challenge

The logo combined several strong elements: a detailed dog portrait, a bandit theme, and a bold display wordmark. The main challenge was bringing them together without making the identity difficult to recognise when it appeared at a smaller size.

  • Capture Roi's recognisable colouring and expression
  • Make the bandit idea clear without letting it overpower the dog
  • Create a visual style that could extend beyond the primary logo

Key decisions

  • I simplified Roi's fur into clear vector shapes while keeping his natural colours and the details that make him recognisable.
  • The eye mask and Western-inspired lettering connect the dog portrait with the “Bandits” name without introducing another separate symbol.
  • I created full, horizontal, and icon-focused versions so the identity could adapt to social media, web layouts, and printed material.
  • Greens and dark neutrals form the supporting palette, allowing Roi's red-and-white colouring to provide the main contrast.

From logo to visual system

The identity needed more than a logo to support a complete website. I created speed lines and tipping agility obstacles that could add energy to a layout without repeating the main character everywhere. Using the same angles, line weight, and green accents keeps the different elements connected.

  • Used directional lines to suggest speed and acceleration
  • Turned familiar agility equipment into playful decorative graphics
  • Applied the elements across the header, footer, and page layouts

Outcome and reflection

The finished system gives Agility Bandits a recognisable personality that works from a small social icon to a complete website layout. Roi makes the brand personal, while the supporting graphics provide enough variation to use the identity without placing the full logo everywhere. This project helped me understand how one central character can become the starting point for a wider and more flexible visual system.

StudioBid

A direct auction identity designed to remain clear and recognisable throughout the digital product.

Role
Brand identity and logo design
Scope
Individual Semester Project 2
Year
2025
Tools
Adobe Illustrator, Figma
Outcome
UI-ready logo system

The brief

StudioBid needed an identity that communicated its purpose as an online auction platform without requiring an explanation. The logo had to fit naturally into the interface, remain recognisable as a small icon, and work across both light and dark backgrounds. It also needed enough personality to distinguish the platform from more traditional auction brands.

Challenge

A gavel is an obvious symbol for an auction, which makes it useful but also very familiar. The main challenge was giving this symbol enough character to feel connected to StudioBid while keeping it simple enough for navigation, favicons, and other small interface placements.

  • Make the platform's purpose immediately recognisable
  • Give a familiar auction symbol its own colour and visual character
  • Create variations for narrow, small, light, and dark placements

Key decisions

  • I reduced the gavel to a bold silhouette so it remains easy to recognise when used alone at icon and favicon sizes.
  • I highlighted “Bid” in vivid pink to draw attention to the platform's main action and give the wordmark a memorable point of contrast.
  • The heavy geometric lettering balances the symbol and gives the identity a confident, contemporary character.
  • I prepared primary, secondary, icon-only, monochrome, and reversed versions, then tested them inside the actual interface rather than only presenting them as separate graphics.

Outcome and reflection

The finished identity is intentionally direct. The gavel communicates the auction concept quickly, while the pink accent and compact logo variations give StudioBid a consistent presence across the product. Designing the identity alongside the interface helped me treat the logo as a working part of the user experience rather than only as a graphic for presentation.

KT Portfolio

A hand-drawn initials mark developed into a personal identity for my design and front-end work.

Role
Identity and logo design
Scope
Independent portfolio project
Year
2025–2026
Tools
Pencil and paper, Adobe Illustrator
Outcome
Flexible personal logo suite

The brief

I wanted my personal identity to bring together the two sides of my work: visual design and front-end development. It needed to feel creative and handmade while fitting naturally into a portfolio built around organic shapes, movement, and illustrated details. The mark also had to work as a small navigation logo as well as part of wider layouts.

Challenge

Combining K and T into one irregular shape made the mark distinctive, but it also created a risk that the initials would disappear when the logo was reduced. The main challenge was keeping the character of the original sketch while making the silhouette and negative space clear enough for practical use.

  • Combine both initials without creating a formal monogram
  • Keep the hand-drawn movement while improving clarity and balance
  • Make the identity work as an icon, wordmark, and reversed logo

Key decisions

  • I began with loose pencil sketches so I could explore how the initials might flow into one shape before making the design more precise.
  • The ink-like silhouette connects the identity to my background in traditional art and to the organic visual language of the portfolio.
  • I simplified the outer contour and adjusted the internal spaces so the K and T remain visible when the mark is used at navigation and icon sizes.
  • I created icon-only, horizontal, vertical, monochrome, outline, and reversed versions for different placements and backgrounds.

Outcome and reflection

The finished mark gives the portfolio a personal signature without using a typical design or coding symbol. It keeps the movement and irregular character of the original sketches while the different variations make it practical across the website and other formats. Designing it for my own portfolio also reminded me that an expressive logo still needs to be tested in the small, everyday places where people will see it most often.

Gemenskapet Science Museum

A curiosity-led museum identity that makes science feel approachable while maintaining the credibility of an educational organisation.

Role
Brand identity and logo design
Scope
Individual Semester Project 1
Audience
Older children and young teenagers
Tools
Adobe Illustrator
Outcome
Web and print logo suite

The brief

Gemenskapet Science Museum needed an identity that encouraged young visitors to explore while still feeling trustworthy to families and schools. The logo had to communicate science and discovery quickly, remain legible across web and print, and adapt from a complete bilingual lockup to a small standalone icon.

Challenge

The museum covered several areas of science, so using only one subject as the central symbol would have felt too narrow. Combining too many references, however, could easily make the logo crowded and difficult to recognise. The main challenge was creating something playful enough for a younger audience without losing the clarity expected from an educational institution.

  • Represent curiosity and discovery rather than one scientific field
  • Keep several small symbols understandable when the logo is reduced
  • Balance a colourful, youthful icon with a clear and credible wordmark

Key decisions

  • I used a magnifying glass as the main symbol because it connects observation, investigation, and the curiosity behind scientific learning.
  • I divided the lens into coloured sections containing molecule, atom, and network symbols to suggest several areas of science without choosing only one.
  • The rounded icon and bright colours make the identity approachable, while the clean sans-serif wordmark gives it a more stable and credible foundation.
  • I added the handwritten Swedish tagline “utforska tillsammans :)” as a warmer, more informal layer that can be removed when space is limited.

Outcome and reflection

The completed identity feels youthful and inviting without losing its educational character. The full logo introduces the museum clearly, while the magnifying-glass symbol can represent it in smaller spaces. Creating horizontal, vertical, monochrome, and reversed versions from the beginning also made the identity practical for both digital and printed applications. This project helped me understand how several visual ideas can be combined into one flexible symbol without making it unnecessarily complicated.

About

Designing with Intention, Building with Care

I’m a UX/UI designer and front-end developer with a professional background in visual design, branding, illustration, and digital interfaces. I bring design and code together to create responsive experiences with clear structure, accessible interactions, and a strong visual identity.

My Story

My path began in visual design and art, with many years of professional work spanning branding, illustration, web design, touchscreen interfaces, and digital layouts. That experience taught me to notice the details that shape an experience: hierarchy, spacing, typography, colour, rhythm, and how people move through an interface.

Wanting to take ideas beyond visual concepts and turn them into working digital products, I studied front-end development at Noroff. Today, I use semantic HTML, modern CSS, JavaScript, TypeScript, React, and REST APIs to build responsive and accessible interfaces. My recent projects include booking, auction, e-commerce, and portfolio experiences with reusable components, authentication, and API-driven content.

What I enjoy most is working where design and development meet: shaping the idea, refining the user experience, and then building it into something real. I like interfaces that feel calm, clear, and easy to use while still having a distinct visual identity.

Outside digital work, I paint fine-art pet portraits in oils. Whether I work with pixels, code, or paint, I care about the same things: clarity, craft, and human connection.
